ANNIBALE / SM8750 — OS3.0.307.0.WPKCNXM
7 November 2026, Asia/Jakarta

STATUS FILE HASIL
Folder ini memuat ABL ELF riset lama dan UEFI ELF Ebl-first eksperimen v8.
Ebl-first diterapkan dalam QcomBds di UEFI, BUKAN dalam ABL. Periksa bagian 10.
Format container, header FV/FFS dan digest payload telah diperiksa offline.
SIGNATURE OEM HASIL PATCH INVALID. Belum layak diperlakukan sebagai image yang
siap di-flash pada Xiaomi retail dengan autentikasi firmware aktif.
Belum ada uji boot, fake lock, entry EFI kustom atau SuperFastboot pada HP.

2. APA YANG DIPATCH

Empat rentang berikut berada dalam PE LinuxLoader CN hasil ekstraksi:

PE 0x3A398: 37 a9 ff 97 -> 20 00 80 52
  BL getter -> MOV W0,#1.
PE 0x3B774: 28 00 80 52 -> 08 00 80 52
  MOV W8,#1 -> MOV W8,#0.
PE 0x3B7B8: ea 03 01 39 -> ff 03 01 39
  STRB W10 -> STRB WZR pada [SP,#0x40].
PE 0x45674: e9 02 00 b0 29 b1 23 91 -> 69 02 00 90 29 25 39 91
  Alamat string unlocked -> locked.

Total 10 byte berbeda pada PE dengan panjang tetap 1179648 byte.
SHA-256 PE sesudah patch:
9b55fb1ee70b3519a947160033d4d9929edf6d045d6dbc0c4e39b23fdf8fffc5

Ini kandidat yang sudah dipetakan di BOOTSTATE_FINDINGS.md, bukan pemanggil
GBL/SuperFastboot baru. Tidak ditambahkan partisi efisp, driver atau menu BDS.
Efek runtime seluruh patch belum dibuktikan. Label locked tidak membuktikan
bootloader terkunci nyata, secure boot diterima, atau attestation berubah.

3. JALUR REPACK DAN TEMUAN BARU

ELF asli mempunyai PT_LOAD di offset file 0x1000, ukuran 0x50000.
LZMA berada di offset ELF 0x1078. Hasil dekompresi berukuran 0x1200C8;
inner FV mulai pada offset buffer 0x8 dan PE pada offset buffer 0xB8.

Script mengganti empat rentang PE, mengompresi kembali, memperbarui ukuran
GUID-defined section dan FFS luar, lalu menghitung ulang checksum header FFS.
Sisa PT_LOAD diisi 0xFF sesuai pola asli. Header ELF dan program header tetap.
SHA-384 PT_LOAD yang baru ditulis di offset ELF 0x51150.

Stream LZMA asli: 311404 byte. Stream hasil: 310149 byte.
Keduanya muat dalam PT_LOAD asli tanpa menggeser hash segment atau sertifikat.
Checksum header FV/FFS dan semua digest segmen yang diperiksa tetap valid.

Namun hash segment MBN v7 mempunyai signature OEM ECDSA P-384/SHA-384:
  Data bertanda tangan: offset ELF 0x51000 sampai sebelum 0x511B0 (432 byte).
  Signature: offset ELF 0x511B0, blok 104 byte.
  DER signature aktual 103 byte, diikuti satu byte padding 0x00.
  Sertifikat: offset ELF 0x51218, ukuran DER 600, 689 dan 724 byte.
  Sisa area sertifikat: 1347 byte 0xFF.

Signature asli berhasil diverifikasi memakai leaf public key yang disertakan.
Signature yang disalin ke kandidat GAGAL karena digest dalam signed data
berubah. Sertifikatnya masih valid satu sama lain; itu tidak memperbaiki
signature image. Memperbarui digest atau memakai qtestsign tidak memberikan
private key OEM. Tidak ada signature OEM baru atau bypass autentikasi dibuat.

Ini batas berbeda dari unlock Android/AVB dan properti yang dimodifikasi
modul spoofing. Log stock perangkat sebelumnya menyebut Secure Boot On.
Modul spoofing tidak perlu dicopot untuk reproduksi offline ini.

Penelusuran entry tetap belum menemukan caller Ebl yang terbukti berjalan
sebelum LinuxLoader pada retail. Jalur pemuatan ABL melalui protokol PIL
tidak boleh disalahartikan sebagai jalur pemanggil Ebl.

4. MENGULANG HASIL PATCH

Jalankan dari root repo menggunakan Python 3.10+ yang mendukung lzma:

  python3 annibale/src/patch.py

Atau dari dalam folder annibale:

  python3 src/patch.py

Untuk memeriksa berkas yang sudah ada tanpa menulisnya:

  python3 annibale/src/patch.py --check

Untuk output baru di luar paket:

  python3 annibale/src/patch.py --output /path/baru/boot.elf --report /path/baru/build-report.json

Script memeriksa hash sumber lengkap, byte asal, batas kompresi, checksum,
digest, payload hasil ekstraksi ulang dan hash keluaran yang dipin. Berkas
output/report yang sudah ada tetapi berbeda tidak ditimpa. Hasil diuji pada
Python/liblzma lingkungan penelitian; jika implementasi kompresor lain
menghasilkan byte berbeda, script berhenti sebelum menerbitkan hasil.

Audit signature opsional, dari root repo:

  python3 -m pip install -r annibale/src/requirements.txt
  python3 annibale/src/verify_signature.py
  python3 annibale/src/verify_signature.py --check

Audit ini tidak membuat signature baru. INVALID untuk kandidat adalah hasil
penelitian yang diharapkan, bukan hasil boot yang berhasil.

Di Linux, cek semua file dari folder annibale:

  sha256sum -c SHA256SUMS.txt

5. FASTBOOT: PEMERIKSAAN DAN BATAS PAKET INI

Bagian ini menjelaskan sintaks yang diminta. Tidak ada perintah di bawah yang
dijalankan oleh script atau oleh penelitian ini pada HP.

Hubungkan HP dalam bootloader fastboot, lalu periksa dari komputer:

  fastboot devices
  fastboot getvar product
  fastboot getvar current-slot
  fastboot getvar has-slot:abl
  fastboot getvar is-userspace
  fastboot getvar partition-size:abl_a
  fastboot getvar partition-size:abl_b

is-userspace=yes berarti fastbootd; ABL termasuk firmware bootloader, jadi
gunakan bootloader fastboot untuk pekerjaan ini. Jika getvar tidak didukung,
jangan mengarang nilai jawabannya. Cocokkan perangkat/build, slot dan ukuran
dengan data yang benar-benar tersedia. Tabel GPT yang dibaca pada penelitian
ini memang memiliki abl_a dan abl_b; akses flash dari fastboot belum diuji.
Status locked/green dari getprop yang di-spoof tidak cukup untuk keputusan ini.

Jika ADB root tersedia, contoh backup baca-saja ke komputer sebelum pengujian:

  adb exec-out su -c 'cat /dev/block/by-name/abl_a' > abl_a.backup.bin
  adb exec-out su -c 'cat /dev/block/by-name/abl_b' > abl_b.backup.bin

Backup partisi penuh dapat lebih panjang daripada file ELF; hash seluruh
backup tidak harus sama dengan hash file ELF 335672 byte. Periksa keberhasilan
command dan simpan backup di luar HP. Tidak ada script backup/flash otomatis.

6. FASTBOOT: FORMAT PERINTAH FLASH

KANDIDAT DALAM PAKET INI MASIH SIGNATURE-INVALID. Contoh berikut HANYA FORMAT
REFERENSI untuk penelitian pada lingkungan yang sudah mempunyai jalur
autentikasi/pemulihan yang dibuktikan, atau untuk image pengganti yang telah
diterima autentikasinya. Ini bukan rekomendasi menjalankannya pada HP retail
pengguna sekarang. Membuat ELF yang benar tidak cukup untuk melewati PIL.

Dari folder annibale, contoh menulis SATU target slot A:

  fastboot flash abl_a OS3.0.307.0.WPKCNXM_abl.elf

Jika slot yang sengaja dipilih untuk pengujian adalah B, formatnya:

  fastboot flash abl_b OS3.0.307.0.WPKCNXM_abl.elf

Pilih salah satu target berdasarkan rencana dan hasil getvar, bukan menjalankan
keduanya berurutan. Jangan memakai abl_ab atau --slot all untuk percobaan ini.
Jangan menjalankan set_active hanya untuk menebak jalur yang akan dipakai.
Menyisakan satu ABL asli tidak menjamin perangkat dapat pulih apabila gagal
sebelum USB fastboot tersedia.

OKAY saat flash membuktikan command tulis selesai, bukan bahwa signature akan
diterima pada boot berikutnya. Paket ini tidak mengeksekusi reboot setelah
flash, dan tidak mengklaim tersedia jalur dry-run fastboot untuk menguji ABL.
fastboot boot ditujukan untuk image boot, bukan tes aman bagi file ABL ELF ini.
Jangan flash berkas ini ke boot, init_boot, vendor_boot atau vbmeta.
Jangan melakukan relock bootloader untuk mencoba kandidat ini.

berkas noauth pengguna pasti kompatibel. Jalur pemulihan tersebut belum diuji.

9. CHECKPOINT EBL-FIRST DAN CONTOH FENRIR

Source penuh terbaru memuat EBL_FIRST_FINDINGS.md dan folder research.
research/ebl_first_stub.bin adalah program ARM64 baru 72 byte, BUKAN image
partisi. Rencana pada hook-plan.json menempatkannya di PE QcomBds pada UEFI:
call RVA 0x5254 dialihkan ke RVA 0x1C900 untuk Ebl Main FV, kemudian meneruskan
LinuxLoader ABL FV bila Ebl kembali. Dua base alamat dan status sukses/error
diuji pada emulator; helper peluncur UEFI dimock. Belum ada eksekusi EFI/HP.

File ABL hasil patch di folder induk tetap versi riset v6 dengan hash bbf89327...
dan tidak mengandung hook ini. Pada v7 hanya program studi yang diterbitkan;
v8 sekarang menambahkan image UEFI lengkap seperti dijelaskan di bagian 10.
Penerapan hook memerlukan autentikasi perubahan UEFI atau jalur tulis RAM awal
yang belum ditemukan. Area padding calon stub belum dibuktikan aman global.

research/certs berisi DER leaf/intermediate/root ABL asli, chain beserta
padding 3360 byte, dan signature asli 104 byte. Semua diekstrak identik dari
default, sesuai permintaan pengguna. Ini sertifikat publik, bukan private key.
Kandidat ABL v6 sebenarnya sudah mempertahankan blok itu secara identik.

Contoh logo MediaTek pengguna menambahkan context-[0] override hash 90 byte
dan memperbaiki alignment sambil mempertahankan cert donor. Mekanisme parser
tersebut belum ditemukan pada jalur Qualcomm yang diperiksa. ABL dan UEFI
stock Qualcomm bahkan memakai tiga cert yang identik, dengan signature image
masing-masing valid; perubahan signed data membuat signature tidak cocok.

Generator hook dan analyzer berada di src pada root source penelitian penuh,
bukan hanya src default-ABL dalam paket annibale. Cara reproduksi lengkap
terdapat pada research/README.md dan EBL_FIRST_FINDINGS.md.

10. IMAGE UEFI EBL-FIRST V8: REPRODUKSI DAN REFERENSI KOMPONEN

File baru berakhiran _uefi_EBL_FIRST_RESEARCH.elf adalah UEFI ELF64 wrapper,
bukan ABL ELF32. Jangan rename menjadi abl.elf atau boot.elf untuk flash ABL.
Hook mengubah call PE QcomBds raw/RVA 0x5254 dari b60a0094 ke ab5d0094, lalu
memasang stub 72 byte pada PE raw/RVA 0x1C900. PE QcomBds berada pada offset
0x3C18F4 BUFFER DEKOMPRESI; LZMA mulai pada offset FILE UEFI 0x4E268.
Jangan memasukkan RVA itu langsung ke hex editor file ELF yang dikompresi.

Stub memanggil Ebl Main FV melalui helper native 0x7D2C. Bila Ebl kembali,
stub melanjutkan LinuxLoader pada ABL FV dengan argumen semula dan kembali
ke RVA 0x5258. Charger/PIL ABL yang berjalan sebelum call tetap ada. Bila
Ebl tidak kembali, LinuxLoader tidak dilanjutkan. ABL tidak dimodifikasi oleh
hook ini dan tidak perlu diganti hanya untuk rancangan Ebl-first tersebut.
Tidak ada payload GBL/SuperFastboot baru yang ditambahkan.

Repack mempertahankan panjang ELF 2839004 byte, program headers, sertifikat,
signature asli dan seluruh file lain. LZMA Main FV 668275 -> 662182 byte.
PAD FFS baru 6096 byte di file UEFI 0xEFD10 menjaga FFS berikutnya tetap pada
0xF14E0. Checksum header/chain file dan SHA-384 payload di 0x2B4150 diperbarui.
Ekstraksi independen menemukan 104 PE, hanya QcomBds berubah, 103 lain identik.
Jumlah byte PE yang berbeda: 63 dalam dua rentang patch 4 dan 72 byte.

Reproduksi dari root repo, tanpa gpt.zip dan tanpa HP:

  python3 annibale/src/patch_uefi_ebl_first.py --check
  python3 -m pip install -r annibale/src/requirements.txt
  python3 annibale/src/verify_uefi_signature.py --check

Hilangkan --check untuk membuat ulang output yang belum ada. Untuk lokasi
baru, tambahkan --output /path/hasil.elf --report /path/build-report.json.
Script menolak basis hash lain, menimpa input atau output berbeda yang sudah
ada. Semua script ini berjalan offline dan tidak menulis partisi perangkat.

Signed range UEFI [0x2B4000,0x2B41B0), signature 0x2B41B0, cert 0x2B4218.
DER signature 102 byte + dua nol; chain 3360 byte. Signature/cert dan 676 FF
trailing dipertahankan identik. Signature stock VALID, hasil INVALID karena
digest dalam signed data berubah. Tidak ada bypass autentikasi dibuktikan.
Padding stub belum terbukti bebas dari seluruh referensi runtime. Console,
input/protokol dan Ebl asli belum dijalankan; emulasi masih memakai helper mock.

Tabel GPT capture menyebut uefi_a dan uefi_b, masing-masing 5242880 byte;
itu bukan bukti izin flash ataupun penerimaan image. Sebelum riset perangkat,
referensi pemeriksaan bootloader fastboot untuk KOMPONEN UEFI:

  fastboot getvar current-slot
  fastboot getvar has-slot:uefi
  fastboot getvar is-userspace
  fastboot getvar partition-size:uefi_a
  fastboot getvar partition-size:uefi_b

Contoh backup baca-saja ke komputer jika ADB root tersedia:

  adb exec-out su -c 'cat /dev/block/by-name/uefi_a' > uefi_a.backup.bin
  adb exec-out su -c 'cat /dev/block/by-name/uefi_b' > uefi_b.backup.bin

Backup 5 MiB lebih besar daripada ELF 2839004 byte. Simpan di luar HP dan
periksa hasil command. File ELF dan backup penuh bukan hash yang sama.

FORMAT REFERENSI SAJA, BUKAN LANGKAH UJI YANG DIREKOMENDASIKAN SEKARANG:
Jika jalur autentikasi dan pemulihan sudah dibuktikan pada lingkungan riset,
format untuk SATU target slot A dari folder annibale adalah:

  fastboot flash uefi_a OS3.0.307.0.WPKCNXM_uefi_EBL_FIRST_RESEARCH.elf

Untuk target B yang sengaja dipilih, ganti hanya target menjadi uefi_b.
Kandidat saat ini signature-invalid; jangan jalankan contoh pada HP retail
hanya karena fastboot menerima command tulis. Jangan flash kedua slot atau
menganggap slot cadangan menjamin pemulihan UEFI. Gagal pada tahap ini dapat
menghilangkan akses fastboot. Tidak ada flash/reboot yang dijalankan di sini.

Bila fastboot masih tersedia dan target A yang sebelumnya diubah, referensi
pemulihan UEFI asli adalah:

  fastboot flash uefi_a src/OS3.0.307.0.WPKCNXM_uefi.elf

Gunakan uefi_b jika hanya target B yang sebelumnya diubah. Jangan memakai
file UEFI untuk partisi abl, boot, init_boot atau vbmeta. Jika fastboot sudah
tidak tersedia, contoh ini tidak dapat memulihkan HP; kompatibilitas jalur
EDL pengguna belum diuji. Tidak melakukan relock untuk eksperimen ini.
